# Inject thinking.display=summarized to restore plaintext thinking

**Priority:** Medium
**Complexity:** Low
**Context:**
- [Building with extended thinking — Claude docs](https://docs.claude.com/en/docs/build-with-claude/extended-thinking)
- [anthropics/claude-code#31326 — empty thinking since v2.1.69](https://github.com/anthropics/claude-code/issues/31326) (closed: not planned)

## Problem Statement

Since Claude Code v2.1.69 (and Claude Opus 4.7 release), `thinking` content blocks come back from the API with `thinking: ""` and only an opaque `signature` blob. The Claude Code TUI extended view (ctrl-o) renders nothing because there's no plaintext to show.

This is not a Claude Code bug. The cause is a model-default change: on Opus 4.7 and "Claude Mythos Preview", the `thinking.display` request parameter defaults to `"omitted"` (empty thinking text + encrypted signature) instead of `"summarized"` (summary text + signature). Documented behavior, server-controlled.

We want plaintext (summarized) thinking visible again in ctrl-o without changing models.

## Current Situation

- Reverse proxy already in place at `~/claude/mitmproxy/`, run via `proxy.sh` (mitmproxy reverse-proxy → `https://api.anthropic.com`).
- `syspatch.py` already mutates outgoing JSON request bodies (currently for `system` prompt patching).
- `flow2jsonl.py` records traffic; signature inspection (`~/tmp/claude-thinking.dat`) confirmed envelope-encrypted protobuf with `claude-opus-4-7` in the header — body bytes have ~7.81 bits/byte entropy, statistically uniform, so we cannot decrypt locally.
- Claude Code is presumably routed through this proxy via `ANTHROPIC_BASE_URL` (verify before testing).

## Proposed Solution

In `syspatch.py:request()` (or a new sibling addon), after the system-prompt patching, inject `display: "summarized"` into the request body's `thinking` field:

```python
thinking = body.get("thinking")
if isinstance(thinking, dict) and thinking.get("type") in ("adaptive", "enabled"):
    thinking.setdefault("display", "summarized")
```

`setdefault` is idempotent: Sonnet 4.6 / Haiku 4.5 already default to `"summarized"`, so this is a no-op there. It only changes behavior for Opus 4.7+ where the model default is `"omitted"`.

The `signature` blob is byte-identical between display modes per docs, so multi-turn continuity is unaffected.

## Open Questions

- Does Claude Code currently send `thinking: {type: "adaptive"}` for Opus 4.7? If it omits the field entirely (relying on server default), the setdefault won't fire because `body.get("thinking")` returns None. If so, we need to *create* the thinking config — but that risks enabling thinking on requests where Claude Code intentionally disabled it. Inspecting captured `traffic.jsonl` for an Opus 4.7 message will answer this in seconds.
- Is `display: "summarized"` accepted on streaming requests the same way, or does it interact with stream framing? Docs imply it works identically; verify.
- Worth filing a Claude Code feature request for a settings.json knob (e.g., `"thinkingDisplay": "summarized"`)? Issue #31326 is closed-as-not-planned, but a focused FR may land differently.

## Notes

- Even with `display: "summarized"`, what comes back is a *summary* generated by a separate model — not Claude's verbatim chain-of-thought. Per docs, full CoT on Claude 4 requires contacting `sales@anthropic.com`; only Sonnet 3.7 returns full thinking by default.
- Alternative considered: patch Claude Code's `cli.js` directly. Rejected — proxy approach is decoupled, survives Claude Code upgrades, and reuses existing infrastructure.
- Alternative considered: downgrade Claude Code to v2.1.68. Rejected — leaves user on a stale CLI permanently.
