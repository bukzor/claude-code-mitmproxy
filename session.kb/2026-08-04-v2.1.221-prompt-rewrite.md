# 2026-08-04: v2.1.221 rewrote the prompt; the patch set went to zero

## How it surfaced

Not by any alarm. In an unrelated session the user asked for an outline of
the served system prompt, then asked which parts looked bloated. Answering
that meant reading the prompt as delivered — which is post-patch, since
`ANTHROPIC_BASE_URL` pointed at the running proxy. Two things in that
outline should have been impossible: an unconditional Fast Mode line and a
full `gitStatus` block, both of which have patches.

## What was actually wrong

Upstream replaced the long-form prompt wholesale in v2.1.221. Headings
before and after:

|---|---|
| `# System` | — |
| `# Doing tasks` | — |
| `# Executing actions with care` | — |
| `# Using your tools` | — |
| `# Tone and style` | — |
| `# Text output (does not apply to tool calls)` | — |
| `# Background Session` | — |
| — | `# Harness` |
| — | `# Scratchpad Directory` |

| — | `# Corrections` |
| `# Session-specific guidance` | `# Session-specific guidance` |
| `# Environment` | `# Environment` |
| `# Context management` | `# Context management` |

The long form has converged on the `# Harness` shape that `README.md`
describes as the Fable-class variant. Whether that is now one shape or two
is unresolved.

Against a live opus-5 capture:

```
$ python3 check_patches.py log/prompt-captures/v2.1.221.b9a_claude-opus-5_0589fbf1d5ac.raw.md
original: 8574 chars
patched:  8575 chars
delta:    +1 chars
```

The `+1` is the known `apply_patches` trailing-newline bug, not a patch
firing. Effective strip rate: zero, against a documented ~32%.

Grep probes for the surviving patch targets in that capture — `additional
working directories` 0, `backwards` 0, `/feedback` 0, `Model family` 0,
`URL` 0, `proactively` 0. The text those patches remove is gone upstream,
so their misses are correct behavior. Only two patches still have a live
target and miss it anyway:

- `strip-git-status` — both `match.d/` variants are shape-wrong. v2.1.76
  expects no blank line after `gitStatus: $REST`; v2.1.128 expects a
  `Git user:` line. The live block has the blank line and no `Git user:`.
- `strip-fast-mode-info` — expects a `<fast_mode_info>` tag. The live text
  is an unconditional `# Environment` bullet. That patch's README already
  flagged itself UNVERIFIED on a stale-version smell; this confirms it,
  and confirms the cause is the wrong shape rather than a stale model name.

## Why nothing was loud

Working as designed, and that is the finding. A `match` miss is silent by
construction — the README argues, correctly, that a miss usually means the
patch is simply out of scope. When *every* patch goes out of scope at once
because upstream rewrote the document, that same rule turns a total failure
into silence. The `search`/`match` split only catches drift *within* a
scope that still exists.

`CLAUDE.md` already names this: "Promotion has no automatic trigger —
additive drift is invisible to every loud mechanism until someone looks."
This was that, in its severe form: not drift *added* to a known shape, but
the known shape being replaced. The standing-maintenance item that would
have caught it — promote captures newer than the newest full-body capture
— was outstanding, with v2.1.221 captures sitting unpromoted in
`log/prompt-captures/` and v2.1.214 the newest in `system-prompts.kb/`.

Worth considering as a follow-on: a check that fires when the aggregate
strip rate falls far below its recorded baseline, since no per-patch rule
can see this class of failure.

## Side observations

- `tool-description-patches.d/` covers only `Monitor` and `SendMessage`,
  neither of which is served to opus-5 in the current shape. The largest
  built-in description served is `EndConversation` — the never-taken path,
  carrying a full policy plus a subsection on background forks calling it.
- The new prompt injects an agent-types listing alongside a standing
  `Do not call the AgentTool unless the user requested it` line. The two
  directly undercut each other.
- The parallel-tool-call directive appears twice in the new shape: in
  `# Harness` and again as the closing line.
- `# Delivering work` (~450 words) and `# Corrections` (~250 words) each
  restate a single instruction five to seven times — accreted patch-on-
  patch prose rather than an edited section. Together they are the largest
  reduction available in the new shape.
