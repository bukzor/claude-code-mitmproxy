# 2026-08-04: v2.1.221 rewrote the prompt for opus-5/fable-5; strip rate fell

## How it surfaced

Not by any alarm. In an unrelated session the user asked for an outline of
the served system prompt, then asked which parts looked bloated. Answering
that meant reading the prompt as delivered — which is post-patch, since
`ANTHROPIC_BASE_URL` pointed at the running proxy. Two things in that
outline should have been impossible: an unconditional Fast Mode line and a
full `gitStatus` block, both of which have patches.

## What changed upstream

v2.1.221 rewrote the prompt **for some models only**, and serves at least
two shapes concurrently:

| | shape | served to |
|---|---|---|
| new | `# Harness`, `# Scratchpad Directory`, `# Delivering work`, `# Corrections` | opus-5, fable-5 |
| old | `# System`, `# Doing tasks`, `# Executing actions with care`, `# Using your tools`, `# Tone and style`, `# Text output` | sonnet-5 |

Both keep `# Session-specific guidance`, `# Environment`,
`# Context management`. The 27k sonnet-5 captures are the old shape plus a
large session-optional `# auto memory` block (~130 lines) — that block, not
a third prompt shape, accounts for the size.

The long form served to opus-5 has converged on the `# Harness` shape that
`README.md` describes as the Fable-class variant. Whether the two are now
byte-identical in their shared sections is still unchecked.

Strip rate by shape:

| capture | original | patched | delta | rate |
|---|---|---|---|---|
| v2.1.221 opus-5 (new) | 8574 | 7824 | -750 | 8.7% |
| v2.1.221 fable-5 (new) | 9832 | 8705 | -1127 | 11.5% |
| v2.1.221 sonnet-5 (old) | 27874 | 23460 | -4414 | 15.8% |
| v2.1.214 long-form (old, promoted) | 17986 | 11103 | -6883 | 38.3% |
| v2.1.212-harness (promoted) | 8341 | 6779 | -1562 | 18.7% |

The regression is real and large — 38% → 9% on the shape opus-5 now gets —
but it is missing coverage of a *new* shape, not a failure against the old
one. The old shape is still served and still patched.

Consequences:

- **A patch that matches the sonnet-5 column may not be sunset.** Six of
  them — `fix-tone-conciseness`, `strip-backwards-compat`,
  `strip-colon-before-tools`, `strip-doing-tasks-bloat`,
  `strip-help-feedback`, `strip-url-restriction` — target the old shape,
  which is still live. Marking those `upstream-removed` would convert a
  working patch into a false regression assertion.
- Genuine sunset candidates are only the ones that match nowhere:
  `strip-output-efficiency`, `strip-tool-preference`, and — pending its
  repair decision — `strip-fast-mode-info`.
- `strip-additional-dirs` matches the promoted v2.1.214 capture but no
  live shape; it needs its own check before being called either way.
- `strip-model-family` and `strip-security-bloat` are shape-independent
  and fire everywhere.

Two patches have a live target and miss it:

- `strip-git-status` — both `match.d/` variants are shape-wrong. v2.1.76
  expects no blank line after `gitStatus: $REST`; v2.1.128 expects a
  `Git user:` line. The live block has the blank line and no `Git user:`.
- `strip-fast-mode-info` — expects a `<fast_mode_info>` tag. The live text
  is an unconditional `# Environment` bullet. That patch's README already
  flagged itself UNVERIFIED on a stale-version smell; this confirms it,
  and confirms the cause is the wrong shape rather than a stale model name.

## Why nothing was loud

Working as designed, and that is the finding. A `match` miss is silent by
construction — the README argues, correctly, that a miss usually means the
patch is simply out of scope. When a whole cohort of patches goes out of
scope at once because upstream rewrote the document for one model class,
that same rule reports nothing. The `search`/`match` split only catches
drift *within* a scope that still exists.

`CLAUDE.md` already names this: "Promotion has no automatic trigger —
additive drift is invisible to every loud mechanism until someone looks."
This was that: not drift *added* to a known shape, but a new shape
appearing beside it. The standing-maintenance item that would have caught
it — promote captures newer than the newest full-body capture — was
outstanding, with v2.1.221 captures sitting unpromoted in
`log/prompt-captures/` and v2.1.214 the newest in `system-prompts.kb/`.

An aggregate strip-rate check is worth considering as a follow-on, since
no per-patch rule can see this class of failure. It must be **per-shape**:
a single global number is dominated by whichever shape happened to be
captured, and here the three live shapes strip at 9%, 11%, and 16%.

## Measurement prerequisite

Both patch directories are `~`-relative, so a shell with a wrong `$HOME`
resolves them somewhere that doesn't exist. Both loaders used to treat
that as "no patches" and return empty, which reports a clean zero-strip
run instead of failing. An empty patch set is never a legitimate
configuration for this proxy, so `load_patches` and `load_tool_patches`
now assert on both the missing directory and the empty result.

Note that an *unset* `$HOME` is not the hazard — `Path.expanduser()` falls
back to a `pwd` lookup by uid and resolves correctly. Only a wrong value
misresolves.

## Side observations

- `tool-description-patches.d/` covers only `Monitor` and `SendMessage`,
  neither of which is served to opus-5 in the current shape. The largest
  built-in description served is `EndConversation` — the never-taken path,
  carrying a full policy plus a subsection on background forks calling it.
- The new prompt injects an agent-types listing alongside a standing
  `Do not call the AgentTool unless the user requested it` line. The two
  directly undercut each other.
- The parallel-tool-call directive appears twice in the new shape: in
  `# Harness` and again as the closing line.
- `# Delivering work` (~450 words) and `# Corrections` (~250 words) each
  restate a single instruction five to seven times — accreted patch-on-
  patch prose rather than an edited section. Together they are the largest
  reduction available in the new shape.
